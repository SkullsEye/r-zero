The six columns the browser model uses

The full system reads 36 columns and builds nine identity families. The model you can run in the Model tab deliberately uses only these, because they are the six things any payments team already has, which is what makes "paste your own file" a real offer rather than a demo.

Missing is not the same as zero. DeviceInfo is blank on 79.9% of rows. A blank identity contributes nothing and receives nothing, and its history features are marked −1 rather than imputed. Getting this wrong in the browser port — JavaScript producing NaN where Python produced 0 — silently corrupted 86% of rows before we caught it.

The second dataset

A method that only works on one file is not a method. The branching ratio was re-estimated from scratch on the ULB European card dataset — different continent, different years, different acquirer, anonymised features, 284,807 transactions at a 0.17% fraud rate.

0.574 against 0.438. Different magnitude, same shape: fraud clusters in time in both, and both sit safely below 1. The estimator was not tuned between the two runs.

What we could not use, and why

Recorded because the negative results shaped the design as much as the positive ones.

Elliptic++ — structurally unable to answer

A Bitcoin transaction graph, and an obvious candidate for testing whether risk propagates across a time split. It cannot: 100% of its edges lie within a single time step and none cross the train/test boundary, so the propagation test is impossible by construction. IEEE-CIS has 14.4% of identities appearing on both sides, against Elliptic's 1.3%. We diagnosed this and dropped the dataset rather than reporting a number from it.

Blocked sources

Kaggle, HuggingFace, Zenodo and UCI were all unreachable from the build environment. ULB was recovered through a GitHub mirror and IEEE-CIS was downloaded by hand. Worth stating because it is the reason the repo ships a deterministic rebuild script rather than a download link: web/build_payload.py regenerates every artefact byte-for-byte from the CSV.
